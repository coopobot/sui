# 网页剪藏

随手记 Sui 提供 Chrome / Edge 扩展，一键把网页保存为 Markdown 笔记，自动进入「收件箱」。
支持两种模式：**智能提取正文**（默认）与**全页快照**——后者会把整页内容（尤其图片）
本地化入库，即便原网页下线，笔记内容也不受影响。本页同时面向**使用者**与**扩展开发者**。

## 1. 安装（Chrome / Edge）

1. 打开浏览器扩展管理页：
   - Chrome：地址栏输入 `chrome://extensions`
   - Edge：地址栏输入 `edge://extensions`
2. 打开右上角「开发者模式」开关。
3. 点击「加载已解压的扩展程序」，选择项目中的 `extension/` 目录。
4. 工具栏出现「随手记 Sui」图标即安装成功。

## 1.1 从打包产物安装（三种路径）

> 本节讲**交付形态**（zip / crx）的安装；源码调试仍见 §4.1。

一条命令产出全部交付物（写入 `extension/dist/`，**已 gitignore**）：

```bash
bash scripts/package_extension.sh
```

| 产物 | 用途 |
|------|------|
| `sui-clipper-<版本>.zip` | 扩展目录内容，**`manifest.json` 在 zip 根**；供「加载已解压的扩展程序」与 Chrome Web Store 上传 |
| `sui-clipper-<版本>.crx` | **CRX3**，用本地私钥签名；供自托管更新 / Chromium 直接安装 |
| `update.xml` | 自托管更新清单（企业策略 `ExtensionInstallForcelist` 用） |
| `sui-clipper-<版本>.sha256` | 产物 sha256 校验清单 |
| `INSTALL.md` | 安装说明（脚本生成，随产物交付） |

签名私钥默认在 `$HOME/.sui/extension-signing-key.pem`（首次打包自动 `openssl genrsa 2048` 生成，
权限 `600`，**不入库**）。注意：**扩展 ID 由签名公钥唯一决定**——换 key 即换 ID，旧 ID 的
`chrome.storage.local` 数据与站点授权**不会迁移**，请务必备份私钥。

### 三种安装路径

| # | 路径 | 命令 / 做法 | 适用 |
|---|------|------------|------|
| ① | **解压 + 开发者模式**（**推荐**） | `unzip extension/dist/sui-clipper-<版本>.zip -d /tmp/sui-clipper`，然后 `chrome://extensions` → 开发者模式 →「加载已解压的扩展程序」→ 选 `/tmp/sui-clipper` | 开发者 / 个人自用 |
| ② | **企业策略 + 自托管更新** | 把 `.crx` 与 `update.xml` 托管到 https（`update.xml` 的 `codebase` 用 `--codebase` 指定真实地址），再下发策略 `ExtensionInstallForcelist` = `"<扩展 ID>;<update.xml 的 URL>"` | 受管机队 |
| ③ | **Chrome Web Store** | 在 CWS 开发者后台上传 `sui-clipper-<版本>.zip`（**zip，不是 crx**） | 对外发布 |

> ⚠️ **CRX 的限制**：Chrome 桌面版（**Windows / macOS**）**不允许**从 Chrome 网上应用店之外
> **直接安装** `.crx`——把 `.crx` 拖到 `chrome://extensions` 或双击它，Chrome 会拒绝并提示
> 「只能通过 Chrome 网上应用店添加」。这是 Google 的 off-store 安装限制，**不是**打包问题
> （签名完全正确也照样被拦）。因此 `.crx` 只在路径 ② 与 **Chromium / Linux 版 Chrome** 上有意义。
> **个人自用请走路径 ①。**
>
> 自托管更新的完整做法、扩展 ID 的推导口径、产物校验命令与三种路径的细节，见打包脚本生成的
> `extension/dist/INSTALL.md`。

## 2. 配置服务端

1. 右键扩展图标 →「选项」。
2. 填写：
   - **服务端地址**：如 `http://192.168.1.10:8080`
   - **用户名 / 密码**：与服务端一致的账号密码（**v0.12.2 起不再手填 Token**；口令只用于换取令牌，登录后即丢弃、不保存）
3. 点击「登录并保存」，自动验证连接；显示「✓ 已登录并保存设置」即可使用。

> **M10 起**：服务端地址与令牌保存在 `chrome.storage.local`——**不再随浏览器账号同步离开本机**，**口令从不保存**。
>
> 站点访问权限也改为**按需申请**：首次对某个站点剪藏时会弹出授权提示，授予后该站点长期可用；
> 未授予时扩展不会也无法读取页面内容（不再申请「所有站点」的静态权限）。

## 3. 使用剪藏

两种方式：

| 方式 | 操作 | 效果 |
|------|------|------|
| 一键剪藏 | 点击工具栏扩展图标 → 选择模式 →「剪藏此页面」 | 按所选模式保存当前网页 |
| 右键剪藏 | 在页面 / 选中文字 / 链接上右键 →「剪藏到随手记 Sui」 | 按**上次使用的模式**保存 |

### 3.1 两种剪藏模式

剪藏前可在弹窗中切换模式（分段控件），选择会被记住，下次默认沿用：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **智能提取正文**（`article`） | 类 Readability 净化：剔除导航、广告、页脚等噪声，只留正文 | 文章、博客、资讯等以正文为主的内容 |
| **全页快照**（`snapshot`，**默认**） | 保留整页结构与文档顺序（标题 / 表格 / 图注等按序呈现），**并保留原页的版式语义**（对齐 / 居中 / 颜色 / 背景 / 缩进），另附一张**整页截图**；`v0.16.0` 起再额外保存**单文件 HTML 原件**并在笔记内嵌预览 | 需要完整留档、正文提取不理想、或页面结构本身就是重点 |

> **`v0.14.1` 起**「全页快照」在**版式语义**上大幅前进一步（详见 [§3.4](#34-全页快照保结构正文--整页截图附件v0141--fr-69)）：
> 正文**块级分段**（相邻块级元素不再被拼成一行）、Markdown 无法表达的版式落为**受限内嵌 HTML 块**，
> 并额外保存一张**整页截图**作为附件——原页改版 / 下线后仍能**像素级**回看。
> 但仍需明确：它**不是** DOM / CSS 的完整复刻。

### 3.2 图片本地化（离线可读）

无论哪种模式，剪藏时都会**尽量把图片本地化**到服务端附件库：

1. 扩展采集页面（对 `article` 与 `snapshot` 一致）：等待完整 DOM、触发懒加载图片。
2. 服务端按优先级取图地址（`src` → `data-src` / `data-original` / `data-lazy-src` → `srcset` 最大图），
   相对地址按页面 URL 解析为绝对地址。
3. 逐张下载图片 → 以 `sha256` 内容寻址存入附件库 → 正文图片引用改写为 `sui://<sha256>`。
4. 本地化失败的图片**降级保留其绝对外链**，不阻断整篇剪藏，并在完成提示中回带
   **「N 张图片未本地化」**。

这样即使原网页下线，已本地化的图片仍可从附件库读取（离线可读）。

> 阈值（可通过 `clip.Options` 覆盖）：单图字节上限 **10 MiB**、单篇最多本地化 **200** 张、
> 总时长上限 **30s**、单图下载超时 **10s**。超出的图片按「降级保留绝对 URL」处理。

### 3.3 剪藏流程

1. 扩展抓取页面完整 HTML（含懒加载图片）发送到服务端。
2. 服务端按所选模式净化：`article` 提取正文 / `snapshot` 保留整页结构，转 Markdown。
3. 正文内的图片尽量本地化，失败者保留绝对 URL；正文开头附来源链接。
4. **每次剪藏新建一条笔记**：同一个网页重复剪藏会**各自成篇**（唯一性按笔记 id），互不覆盖。
5. 笔记自动进入客户端的「收件箱」——判据是**不可变的剪藏来源标记**（服务端 `source_url` →
   客户端 `sourceUrl`；`source_device` 为 `clip:web-extension`）。

> 提示：想「更新」某一篇就在客户端里编辑它（修订历史兜底）；重复剪藏同一个网页会**多出一篇**新笔记。

### 3.4 全页快照：保结构正文 + 整页截图附件（`v0.14.1` / FR-69）

「全页快照」现在做两件事，**互为补充**：

| 产出 | 内容 | 用途 |
| --- | --- | --- |
| **保结构正文** | **Markdown 主干**（分段、标题、列表含嵌套与任务项、表格、引用、代码块、图片尺寸、`<br>`）+ **受限内嵌 HTML 块**（对齐 / 居中、文字颜色、背景色、边框、缩进等 Markdown 表达不了的版式） | 可编辑、可搜索、可同步的结构化内容 |
| **整页截图附件** | 滚动拼接的**整页位图**（含视口之外的正文），作为笔记的**附件**（`sui://<sha256>`）在正文末尾引用 | 原页改版 / 下线后**像素级**回看「当时长什么样」 |

**正文为什么能保版式**：服务端净化前先识别**块级结构**（相邻块级元素之间一律分段，不再像旧版那样把
`<div>行1</div><div>行2</div>` 拼成「行1行2」一行）；只有**带版式信息**的段落才落成内嵌 HTML 块
（形如 `<div style="text-align:center">…</div>`），其余仍走普通 Markdown——标题 / 列表 / 表格 / 引用 /
代码块等既有能力**一项不丢**。HTML 块是**正本里的字面字符**（源码模式逐字可见可编辑），
客户端在预览与格式模式下按**同一套白名单**渲染，格式模式把它当作**原子块**整块呈现、整块删除。

**截图怎么来的**：浮层里选「全页快照」并点剪藏后，扩展在**同一次操作**中滚动页面逐屏截图，
在画布上纵向拼接并压缩为 JPEG，随**同一个**剪藏请求内联上传（**不新增接口、不额外申请权限**——
只用既有的 `activeTab`，**不启用**调试器权限）。服务端按内容寻址入库为附件并在正文末尾写
`![整页截图](sui://<sha256>)`。

**体积与降级**：

- 截图载荷上限 **5 MiB**（base64）、拼接高度上限约 **16000 设备像素**、总耗时上限 **20 s**；
  先降 JPEG 质量、再降高度，**仍超限就放弃截图**（服务端请求体上限为 8 MiB）。
- **采集 / 拼接 / 压缩 / 上传任一环节失败都不影响剪藏成功**——剪藏结果照常返回（笔记可用、正文完整），
  只是**没有**末尾那张截图。
- 截图必须发生在**用户点击剪藏的那一次操作内**（`activeTab` 授权只在用户手势后有效），
  所以不能延后到后台去补。

**已知限制**：

- **固定定位元素会在拼接接缝处重复**：页面上 `position: fixed` 的吸顶导航、悬浮客服按钮等，
  每一屏截图里都会出现一次，拼接后就会在接缝处重复出现（可稳定复现）。本次**不修**——
  彻底解决需要启用浏览器调试器协议权限，与「能用 `activeTab` 就不加宽权限」的口径冲突。
- **长页面可能主动放弃截图**（超出体积 / 高度 / 耗时闸门）。
- **截图不是网页归档**：单张有损 JPEG，不含可选中文本与链接；语义内容仍以正文为准。
- `article`（智能提取正文）模式**不产生** HTML 块、**不采集**截图、**不产生网页原件**，行为与 `v0.14.1` 之前**完全一致**。

### 3.5 网页原件与内嵌 WebView（`v0.16.0` / FR-83）

`snapshot` 模式在 Markdown 正文之外，额外保存一份**单文件 HTML 原件**：

- 扩展在采集时把可读取的样式表**内联**进克隆 DOM，剔除脚本 / 事件属性 / `iframe` / 表单控件，
  再发送给服务端；服务端二次收口并注入 CSP，按 sha256 内容寻址存为 `mimeKind = webclip` 的附件。
- 笔记正文头部出现 `[网页原件](sui://webclip/<sha256>)`；客户端预览态把它渲染为**内嵌网页**
  （原布局 / 颜色 / 对齐），格式态是原子卡片，双击全屏。
- WebView **禁用 JavaScript、禁止联网、拦截外部导航**；桌面 / 移动通过自定义 scheme 按需读取
  `sui://` 图片（不把整页图片内联进 HTML），Web 端在 8 MiB 预算内才替换为 data URI。
- 原件超过 **12 MiB**、WebView 不可用（如 Windows 无 WebView2 Runtime）、Linux 或原件尚未同步时，
  客户端显示「整页截图 + 打开原件」降级卡片；剪藏本身仍成功。
- **有原件时截图不再追加到正文**，但仍作为附件保留供降级使用。

**已知限制**：跨域样式表现在由**服务端**拉取并内联（扩展只保留 `<link>`，不再受浏览器 CORS 限制）；
CSS 背景图 / 字体 / 依赖 JS 的动态内容仍可能未完整保留；原件保存的是采集时刻的 DOM。
**`v0.16.1` 之前剪藏的旧笔记**没有保留 `<link>`，样式会缺失，需要**重新剪藏一次**。

### 3.6 选择正文区域剪藏（`v0.16.2` / FR-90）

首页、列表页、频道页的页头 / 导航 / 页脚往往很多；自动提取可能不理想。可以用**手动选择正文**：

1. 打开扩展浮层，点「**选择正文区域剪藏…**」（或页面右键 →「选择正文区域剪藏」）。
2. 页面顶部出现提示条；鼠标移到正文容器（如 `<article>` / `<main>` / 内容 `<div>`）会高亮。
3. 点击选中；`Esc` 取消。
4. 扩展只保留 `body → 选中元素` 的**祖先链**与选中内容，删除每一级的兄弟节点
   （页头 / 页脚 / 侧栏通常就是这些兄弟）；`<head>` 样式与外部样式表保留，服务端拉取并内联。
5. 固定按 `snapshot` 处理（Markdown + 网页原件）；**不采集整页截图**（避免把页头页脚又带回来）。

> 提示：尽量选**包含正文的最大容器**（不要只选一个段落）；如果选中的容器依赖兄弟节点排版，
> 可能只保留选中部分。旧剪藏没有 `<link>`，如需正确样式请重新剪藏一次。

## 4. 开发与调试

### 4.1 加载调试

1. Chrome → `chrome://extensions` → 开发者模式 →「加载已解压的扩展程序」→ 选择 `extension/`。
2. 右键扩展图标 →「检查」打开 DevTools 调试 popup / background。
3. 改代码后在扩展管理页点「重新加载」。

### 4.2 模块说明

| 文件 | 职责 |
|------|------|
| `manifest.json` | MV3 清单：权限（activeTab / storage / scripting / contextMenus）+ **`optional_host_permissions`（`http/https`，按需申请）** |
| `shared.js` | 共享逻辑：**会话层**（账号密码登录、双令牌存取、401 单飞刷新 + 重放一次、明文地址警示）、模式记忆、整页采集（懒加载触发）、**整页截图采集**（`suiPlanScreenshotSlices` 分屏规划纯函数 / `suiCaptureScreenshot` 滚动拼接 / `suiEncodeScreenshotWithinBudget` JPEG 质量阶梯与体积闸门）、剪藏请求（含可选 `screenshot` 载荷）与结果文案（popup 与 service worker 共用） |
| `popup.html/js` | 弹窗：模式分段控件 + 当前页信息 + 剪藏按钮 + 状态反馈 |
| `options.html/js` | 设置页：**服务端地址 + 账号 + 密码登录**（v0.12.2 起不再手填 Token）、已登录态与退出登录、明文地址警示（凭据存 `chrome.storage.local`） |
| `background.js` | service worker：右键菜单创建 + 菜单剪藏（沿用上次模式）+ badge 状态 |

### 4.3 剪藏数据流

```
popup/background
  → chrome.scripting.executeScript（shared.js 的采集函数）
      · img.loading = eager；用 data-src/data-original/data-lazy-src 回填 src
      · 滚动整页触发 IntersectionObserver 懒加载；有界等待待加载图片
  → 【v0.14.1，仅 snapshot】整页截图：
      · 内容脚本滚动并回报 innerHeight / scrollHeight / dpr / scrollY
      · chrome.tabs.captureVisibleTab 逐屏取图（每秒 2 次速率约束）
      · canvas 按 scrollY * dpr 纵向拼接 → JPEG 质量阶梯压缩（超限即放弃）
  → POST {serverUrl}/api/v1/clips  {url, title, html, mode[, screenshot{filename,dataBase64}]} + Bearer token
  → 服务端 clip：按 mode 净化（article 提正文 / snapshot 块级分段 + 版式落受限内嵌 HTML 块）
  → 图片本地化：下载 → sha256 → blob.Put → 正文改 sui://；失败降级保留绝对 URL
  → 【v0.14.1，仅 snapshot】截图载荷校验 → sha256 → blob.Put → 附件映射随笔记入库
      · 正文末尾追加 ![整页截图](sui://<sha256>)；非法 / 超限 / 失败一律静默忽略（剪藏仍成功）
  → 每次生成新 noteId 新建笔记（source_device=clip:web-extension；source_url 记来源标记，不判重）
  → 响应回带未本地化图片数 → 扩展提示「剪藏成功 vN（M 张图片未本地化）」/「…（含整页截图）」
  → WebSocket 广播 changed → 客户端收件箱自动刷新
```

### 4.4 自动化门禁

会话层（登录 / 刷新 / 明文警示）有 **Node 侧自动化用例**，无需浏览器即可跑：

```bash
node --test extension/test/*.mjs   # Node >= 18，无第三方依赖
```

`session_test.mjs` 覆盖 9 项：登录写入双令牌且**不落口令**、登录失败 / 锁定文案、访问令牌到期前**主动刷新**、
401（`token-expired`）**单飞刷新 + 重放一次**、**并发只刷一次**、刷新被拒清令牌并保留地址、
未登录提示、明文地址警示（公网 `http` 警示 / 本机与私网不警示）、剪藏请求带会话与模式。

`screenshot_test.mjs`（`v0.14.1`）覆盖 12 项：`suiPlanScreenshotSlices` **分屏规划纯函数**
（视口 / 文档高度 / 设备像素比 / 高度上限）、`captureVisibleTab` **每秒 2 次**速率下的等待节奏、
JPEG **质量阶梯**与 `SUI_SHOT_MAX_B64` 载荷闸门、`SUI_SHOT_MAX_HEIGHT` 截断、总耗时上限、
任一环节失败**静默降级**、`screenshot` 载荷随剪藏请求上行、完成文案「剪藏成功 vN（含整页截图）」。

> 仍需**真机手测**的部分：popup / options 界面呈现、站点权限按需申请弹窗、
> 浏览器重启后的免密剪藏 — 清单见 [故障排查](../troubleshooting.md) 与本版交付记录。

### 4.5 添加图标（可选）

manifest 可声明 `action.default_icon` / `icons`；生成 16/32/48/128px PNG 放入
`extension/icons/` 并在 manifest 引用。
