# ADR-005：网页剪藏采用 Chrome 扩展（Manifest V3）

- 状态：已接受
- 日期：2026-09-25

## 背景

用户需要把网页内容快速剪藏为笔记。需要一个浏览器侧入口，且要复用服务端既有的
鉴权与数据模型，避免另建一套写入通道。

## 决策

- 剪藏入口做成 **Chrome 扩展，Manifest V3**。
- 扩展通过服务端的 **剪藏接口（clips）** 写入，走与客户端相同的鉴权（Token）与
  数据模型。

## 理由

- MV3 是 Chromium 系当前主推规范，长期可维护。
- 复用既有接口与数据模型，服务端无需为剪藏单独建模。
- 剪藏结果与普通笔记同构，可被多端同步。

## 后果

- 正面：入口轻量、端上零安装依赖、数据天然同步。
- 负面：MV3 的 service worker 有生命周期限制；且仅覆盖 Chromium 系浏览器。
- 缓解：剪藏逻辑尽量无状态、可被事件驱动；后续如需可扩展到其他浏览器。
