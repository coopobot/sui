# ADR-004：附件采用内容寻址与按需拉取

- 状态：已接受
- 日期：2026-09-25

## 背景

附件（图片、文件）体积远大于文本。若把附件字节随笔记一起全量同步，将带来
带宽浪费与端上磁盘膨胀，尤其是多设备场景。

## 决策

- 附件按 **sha256 内容寻址** 存储，天然去重。
- 同步策略（**Plan B**）：
  - 元数据（名称、大小、sha256）随笔记全量同步；
  - 字节 **按需拉取**（首次访问某附件时才下载）；
  - 客户端用 **LRU 缓存** 限制本地附件占用上限。

## 理由

- 内容寻址使相同文件只存一份，服务端与端上均省空间。
- 按需拉取显著降低同步流量与首屏等待。
- LRU 上限避免端上磁盘被附件拖垮。

## 后果

- 正面：省空间、省带宽、可扩展。
- 负面：离线时未缓存的附件不可用；Web 端附件字节目前仅暂存内存，刷新即失。
- 待办：服务端尚未实现附件配额与回收策略。
