# ADR-001：选择 SQLite 作为存储

- 状态：已接受
- 日期：2026-09-25

## 背景

「随手记 Sui」是离线优先、多端同步的 Markdown 笔记应用，需要：

- 客户端在无网络时也能完整读写；
- 端上有关系型、可复杂查询（笔记本、标签、置顶、搜索）的本地存储；
- 服务端可被用户自托管，尽量零运维。

## 决策

- 客户端本地持久化使用 **SQLite**，通过 **drift**（类型安全 DSL + 迁移）访问。
- 服务端初期同样使用 **SQLite**，驱动为 **`modernc.org/sqlite`**（纯 Go 实现，免 CGO）。

## 理由

- 离线优先必须有本地关系型存储，文档型/纯内存方案难以支撑标签、笔记本等关联查询。
- SQLite 单文件、零运维，契合「自托管、简单可控」的产品定位。
- drift 提供编译期校验的查询与版本迁移（当前 `schemaVersion = 5`）。
- `modernc.org/sqlite` 免 CGO，交叉编译与部署无需额外工具链。

## 后果

- 正面：双端统一用 SQL，心智一致；部署简单；类型安全。
- 负面：SQLite 并发写受限（WAL 下单写多读），大规模多租户场景需迁移。
- 缓解：服务端 `store` 层已做抽象，未来可平滑替换为 PostgreSQL。
