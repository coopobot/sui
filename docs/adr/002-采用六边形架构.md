# ADR-002：采用六边形架构并抽出 note_core

- 状态：已接受
- 日期：2026-09-25

## 背景

项目需要覆盖多端（Flutter 桌面 / 移动 / Web）与服务端。若把业务逻辑写在
UI 层，将导致：核心逻辑无法脱离 Flutter 单测、各端重复实现、平台差异四处散落。

## 决策

- 抽出 **`note_core`**：纯 Dart 核心（不依赖 Flutter），承载领域模型、同步逻辑
  与端口（port）定义。
- **`flutter_app`** 作为适配层（adapter），负责 UI 与平台实现。
- 平台差异使用 **条件导入** 隔离：`dart.library.io`（原生）与
  `dart.library.js_interop`（Web）成对提供同一接口的实现。

## 理由

- 核心可脱离 UI 进行单元测试，提升可靠性与回归速度。
- 各端共享同一份领域与同步逻辑，避免重复实现和不一致。
- 替换平台实现（如存储、网络）不影响核心，符合依赖倒置。

## 后果

- 正面：可测试、可复用、边界清晰。
- 负面：需要维护抽象层，初期复杂度上升；条件导入文件需成对维护，易漏改。
- 缓解：以「核心纯 Dart、不引 Flutter」为硬约束，并在评审中检查条件导入成对性。
