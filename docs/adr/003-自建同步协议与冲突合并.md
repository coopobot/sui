# ADR-003：自建同步协议与「永不丢文本」的冲突合并

- 状态：已接受
- 日期：2026-09-25

## 背景

多端同步需要处理并发写入。产品底线是 **任何情况下都不能静默丢失用户文本**。

## 决策

- 采用基于 **`base_version`** 的乐观并发控制：
  - 客户端携带其认为的服务端版本推送；
  - 服务端版本不匹配时返回 **`409`**，拒绝写入。
- 冲突由客户端解决：拉取服务端最新版本后，按 **启发式规则合并**
  （标题、正文保留双方文本拼接，附件取并集），再以新 `base_version` 重试。
- 不做静默覆盖。

## 理由

- 相比 CRDT/OT，基于版本的乐观并发实现简单、易调试，且天然支持离线。
- 启发式合并保证文本不丢失，用户可事后人工整理，符合「不丢数据」底线。

## 后果

- 正面：实现简单、可离线、无文本丢失。
- 负面：合并结果可能出现冗余内容；无字符级自动合并。
- 演进：未来可引入 CRDT 或 OT 提升合并质量，协议已预留版本字段。
