# 故障排查

汇集使用与开发过程中最常见的问题及排查思路。若未覆盖，欢迎通过
`CONTRIBUTING.md` 的渠道反馈。

## 使用类问题

### 客户端连不上服务端？

1. 确认服务端已启动：`curl http://<host>:8080/healthz` 应返回 `{"ok":true,...}`。
2. 确认「同步设置」里的地址与端口正确（跨设备用机器 IP 或域名，不要用 `127.0.0.1`）。
3. 跨设备时确认防火墙放行端口。
4. Web 端跨域问题已由服务端 CORS 解决；若仍失败，检查反代是否透传。

### 剪藏扩展提示「登录已失效，请重新登录」/ 剪藏返回 401？

v0.12.2 起扩展用**账号密码登录**换取令牌（令牌存 `chrome.storage.local`，访问令牌 30 分钟、
刷新令牌 30 天，过期自动**单飞刷新**）。出现该提示说明刷新令牌已过期或被吊销
（如在其它端执行过「登出全部会话」）——在扩展设置页**用账号密码重新登录一次**即可。
若升级前一直在用手填的长期 Token，本版需重新登录一次（旧令牌自 M10 起已失效）。

### 剪藏结果没有正文？

部分网页（如纯 JS 渲染的单页应用）正文在脚本执行后生成。可改用**全页快照**模式（浮层模式分段
控件切换到「全页快照」），或先选中网页文字再右键剪藏。

### 剪藏提示「N 张图片未本地化」/ 图片加载不出来？

单图下载失败或超出限额的图片会**降级保留其绝对外链**，因此原站图片失效后这类图片无法显示。
限额为单图 **10 MiB**、每篇 **200** 张、总时长 **30s**。可确认服务端能否访问外网、目标图片是否
需要登录 / 防盗链；已本地化的图片则不受原站影响（存于附件库、正文以 `sui://` 引用）。

### 剪藏提示成功，但客户端的「收件箱」里看不到这篇笔记？

**已在 `v0.13.2` 修复**。根因：「收件箱」原先按 `source_device` 的 `clip:` 前缀过滤，而该字段是
**「最近一次修改的来源设备」**——笔记一旦被任一客户端上传过（本地编辑、单项重试、「全部重新同步」
核对补齐），标记就被改写成本机 `deviceId`，笔记从此只在「全部笔记」里可见。
现在按**不可变的剪藏来源标记**（服务端 `notes.source_url`，随 `pull` 下行为 `sourceUrl`）判定。
若你在旧版本上已经中招：**升级客户端后第一次同步**即会把这类剪藏笔记送回收件箱（服务端标记一直在），
无需手工处理。

**`v0.16.0` 起新增标签兜底**：剪藏成功会自动挂 `#网页剪藏` 标签，收件箱判据 = `sourceUrl` /
`clip:` 前缀 / 该标签三者之一。若某篇老剪藏连 `sourceUrl` 也丢了，只要它有这个标签仍会出现在收件箱；
也可以手动给它打上该标签。剪藏笔记「移动到…」里的「**收件箱**」是独立目标（仅剪藏笔记显示），
移回后归属变为未归类并重新出现在收件箱。

### 剪藏报「失败」，但客户端里其实已经有了这篇笔记？

**已在 `v0.13.2` 修复**（表现为浏览器侧 `Failed to fetch`）。根因：剪藏路由原先只延长**读**期限，
而页面媒体本地化预算 **30s** 大于全局 `WriteTimeout` **10s** —— 图多 / 图慢时响应被写期限切断，
**笔记其实已落库**，客户端却拿不到响应。现已把剪藏路由的**读 + 写**期限一并延长。
（顺带说明：这类「处理慢」与「图片未本地化」是两回事——图片本地化失败只会降级保留外链。）

### 两个设备都改了同一篇笔记，会丢内容吗？

不会。冲突自动合并，双方内容都会保留（冲突段落带标记分隔）。原理见
[系统架构 · 同步协议](architecture.md#4-同步协议与冲突解决)。

### 登录提示「登录尝试过于频繁，请 N 秒后重试」？

v0.12.2 起服务端内置**登录失败防护**（FR-59）：按「用户名 + 来源」统计连续失败，≥5 次起
指数退避（1s → 2s → 4s…上限 30s），≥10 次锁定 **15 分钟**；锁定期内**即使密码正确也会被拒**。
解锁方式（任一）：等待窗口到期；**重启服务端**（计数只驻内存，重启即清零）；
或用 `SUI_LOGIN_GUARD=0` 启动以临时关闭防护。阈值可用 `SUI_LOGIN_*` 环境变量调整
（见[部署指南 · 登录失败防护](deployment.md#11-登录失败防护与反向代理限流v0122--fr-59)）。

### 离线时某些附件打不开？

未缓存到本机的附件离线打不开（卡片显示「未下载」），联网后点击即可下载；
离线时新添加的附件仍会挂到笔记上（卡片显示「待上传」），联网后自动补传。

### 本地磁盘被附件占满？

附件不会全部下载到每台设备，只有真正打开过的才缓存，且总量受「缓存上限」约束
（默认 512MB，可在同步设置里调整）。超出上限时，最久未打开且没有被任何笔记引用的
附件会被自动清理，再次打开会重新下载。详见
[系统架构 · 附件存储策略](architecture.md#5-附件存储策略客户端侧)。

### 界面显示某些笔记是「仅本地」/ 换了服务端后数据没上来？

**「仅本地」= 云端从来没有这个条目**（不是「上传失败」，而是服务端根本没有它）。常见成因两种：

- 这台设备还没连过服务端：先在「同步设置」里连上，再跑一次「全部重新同步」。
- 换了服务端 / 换了数据目录，或服务端被重建、回滚：客户端会发现「云端已经不是原来那一份」，
  并弹出标题为「**云端数据已更换 / 重建**」的**三选一**对话框（用本地数据补齐到云端 /
  以云端为准（不补齐）/ 取消）。在你做出选择之前，它**不会上传、也不会清空任何一端的数据**；
  选「以云端为准（不补齐）」时本机独有的数据**不会被删除**，只会降级为「仅本地」且不再自动上传。

处置步骤：先跑一次**「全部重新同步」**（桌面端菜单「同步 → 全部重新同步」，或「同步设置」
对话框里的同名面板）；仍卡住的条目用它的**「立即上传 / 重试」**单项处理（只影响这一项），
把鼠标停在状态图标上可看到具体失败原因。详见[用户指南 §4](guides/user-guide.md)。

### 导入后报告显示「未本地化资源 N」，图片 / 附件不见了？

导入 HTML 时，正文里引用的图片与附件需要**在本地取到字节**才会入库（正文改 `sui://<sha256>`）；
取不到就**降级**：图片保留 alt 文本、链接保留链接文字，并计入「未本地化资源」。

常见原因：

- **资源目录没一起导入**：印象笔记「导出为多个网页」会把图片放在**同名资源目录**里
  （实测为 `<笔记标题> files/`）。只选 `.html` 文件（或只复制了 HTML）就会缺图——
  用「**选择文件夹…**」导入整个导出目录即可；
- **在 Web 端导入**：浏览器拿不到同级文件，相对资源一律降级（桌面 / 移动端不受影响）；
- **远端图片**：HTML 里的 `http(s)://` 图片**不会被下载**（导入不出网），显示依赖原地址是否还在；
- **非图片附件**：印象笔记官方 HTML 导出对 PDF / 压缩包等**没有可用链接**，只能保留显示文本。

### 导入的 txt 是乱码？

`.txt` / `.md` 目前只识别 **UTF-8（含 BOM）与 UTF-16 LE / BE**。用 Windows 记事本存成
**GBK / GB18030** 的中文文件会以替换字符降级（报告标注「编码可能不正确」）——
请先用编辑器「另存为 UTF-8」再导入。

### 重复导入同一个文件，笔记会翻倍吗？

**本机范围内不会**：导入按「标题 + 正文」的内容指纹去重，重复项计「跳过 · 重复」。
但去重**不跨设备**——A 端导入并同步到 B 端后，在 B 端再导入同一文件会产生第二份，可直接删除。

### 导入后笔记「挤成一行」、或正文里出现 `<br>` 符号？

已在 **`v0.13.1`** 修复。根因：**旧版印象笔记「导出为网页」**（`exporter-version: YXBJ`）的正文
结构（`<a name="…"/>` 不闭合 + `<span>` 里嵌 `<div>`）过去被当成**一个段落**，段界只能退化成行内
`<br>`。修复后段落 / 标题 / 列表正常还原，段落内的换行写成**真换行**。

处理办法：**升级客户端后重新导入一次**（把已导入的这批笔记删除，再选中目标笔记本 →
「文件 → 导入文件…」→「选择文件夹…」；删除后重新导入**不会**被去重挡住）。

> **表格单元格内**的换行仍以 `<br>` 存在于正本中——这是 GFM 管道表「不支持多行单元格」的限制，
> **格式模式会把它渲染成换行**，不会露出字面量标签。

### 导入后「附件」显示错乱（正文里露出 `](sui://…)` 残余、附件名前面多一个 `!`）？

已在 **`v0.13.4`** 修复。根因：印象笔记导出里的「链接包图片」形态
（`<a href="…文件.pdf"><img src="…缩略图.png" alt="…文件.pdf"></a>`，实测 29 篇里 7 处）被导入器组合成
**嵌套引用** `[![名字](sui://缩略图)](sui://文件)`；而客户端识别 `sui://` 引用用的是**扁平正则**
（只认单层 `![…]` / `[…]` + `sui://…`）——它会把 `![名字` 整段吃成标签、sha 取内层图片，剩下的
`](sui://文件)` 就当普通文字渲染出来。

处理办法：**升级客户端后重新导入一次**（删除这批笔记再导入即可）。修复后的正本是**单条扁平引用**：
`[文件名.pdf](sui://<sha256>)`（附件单元，点击即可打开/预览；图片仍是 `![…](sui://…)`）。
装饰性缩略图不再单独挂成附件，因此附件清单会比旧版导入**少几条**（属预期）。

### 导入后列表前面出现反斜杠（如 `1\. LiblibAI·哩布哩布AI`）？

已在 **`v0.13.5`** 修复。原因：导入器为了「源文本里**字面**的 `1. ` 不被当成列表」，会给这类行加
转义（`1. ` → `1\. `）；而转换器**自己生成**的列表标记也被一并转义了——Markdown 上会退化为字面
文本，且**格式模式不渲染转义**，于是反斜杠直接显示出来。

处理办法：**升级客户端后重新导入一次**（删除这批笔记再导入即可）。修复后：真正的 `<ol>` / `<ul>`
一律是**真列表**（`1. ` / `- `），来源里手写的编号段落（如「2. 每月需覆盖的收入」）也按编号项呈现
（编号取自字面值），**任何情况下都不再出现 `\.`**。

> 同一补丁还修掉一个**内容丢失**：`<ol>` 里作为**兄弟**出现的 `<ul>`（剪藏常见的非法嵌套）此前
> 会被整段丢弃，某些网页剪藏笔记只剩三成内容；现在会作为前一个列表项的子列表保留下来。

### 粘贴没有保留原格式（粘进来是纯文本）？

先确认三点：**平台**、**粘贴方式**、**来源**。

| 检查项 | 说明 |
| --- | --- |
| 平台 | 剪贴板的 **HTML 表示**目前**只在 Windows 与 Android 上支持**（Windows 读系统的 HTML 剪贴板格式、Android 读 `ClipData` 的 HTML 项）。**macOS / Linux / Web 本轮未实现** → `Ctrl+V` 会**回落为纯文本**。这属**已知限制**，不是故障 |
| 快捷键 | `Ctrl / Cmd + V` 才是「保留格式」；`Ctrl / Cmd + Shift + V` **恒为纯文本**（这是设计行为） |
| 来源 | 有些应用只往剪贴板放纯文本（终端、部分编辑器的「复制为纯文本」、某些截图工具）；此时没有 HTML 可读，只能回落纯文本 |

**怎么确认「HTML 路径」真的生效了**：粘进来的内容里如果出现**颜色 / 背景色 / 字号**，
或原样的**有序列表编号、嵌套层级、表格**，就说明走的是 HTML 路径——纯文本回落只会得到无格式文字。

**其它已知行为**：剪贴板 HTML 超过 **4 MiB**、内联（`data:`）图片单张超过 **8 MiB** 时按降级处理
（截断 / 去图 / 该图降级为替代文字），不会整体失败；指向网页的**远端图片保留原网址**，
粘贴过程**不会联网下载**。任何一次粘贴都可以用 `Ctrl+Z` **一次撤销**。

### 快照正文里出现 `<div style="text-align:center">…</div>`，这是坏了还是能编辑？

这是**全页快照**（`v0.14.1` / FR-69）**有意保留的版式信息**，不是残留脏数据。
Markdown 无法表达「居中 / 颜色 / 背景 / 缩进」这类版式，所以它们以**受限内嵌 HTML 块**的形式
**直接存在笔记正文里**（正本仍是 Markdown，HTML 只是其中一种**方言片段**）。

| 位置 | 行为 |
| --- | --- |
| 源码模式 | **逐字可见、可全选复制、可直接编辑**——把它整段删掉，就回到纯 Markdown 的观感 |
| 预览模式 | 按受限样式渲染（居中 / 颜色生效），与 Markdown 段落**按原文顺序**混排；**不显示**标签原文 |
| 格式模式 | 视为**一个整体（原子块）**：不显示 `<div …>` 原文、光标不会停在块内字符之间；单击选中**整块**，在块后按**退格 / 删除**一次即**整块删除**（一次撤销可恢复） |

**安全口径**：块内只允许白名单标签与白名单样式（脚本、`on*` 事件属性、`class` / `id`、外链 CSS、
`iframe` 一族**永不出现**）；客户端渲染这些块时**不发起任何网络请求**（块内指向外网的图片**只占位**），
`javascript:` / `data:` / `file:` 等协议**不会**被渲染成可点的链接。

**老笔记**：`v0.14.1` 之前剪藏的纯 Markdown 快照笔记渲染结果**完全不变**，本次**不迁移**历史数据。
**整页截图**若缺失（采集失败 / 体积超限 / 无站点授权），说明该次没能采集到，**不影响**笔记与正文。

### 分割线应该怎么写？「标题 + 下一行 `---`」为什么还是标题？

**点工具栏「分割线」（或 `Ctrl / Cmd + Shift + -`）不会把上一行变成标题**：插入时 `---` **上方保证一个空行**、
**下方不补空行**，正本即 `段落1\n\n---\n段落2`——这是标准 Markdown（与 Gitea / GitHub / Typora 一致），
`---` 独占一行即构成主题分隔线。

只有**手写**「`文字` 换行后紧跟 `---`」（**中间没有空行**）才是 **setext 二级标题**——这不是本产品的特殊行为，
而是所有 Markdown 工具的一致规则；格式模式与预览模式**判定一致**。要二级标题，直接写 `## 标题` 更明确。

| 你想要的 | 怎么写 |
| --- | --- |
| **一级标题** | `# 标题`；或下一行写 `===`（setext 一级标题） |
| **二级标题** | **`## 标题`**（推荐）；或 `文字` 换行后紧跟 `-` / `---`（setext 二级标题） |
| **分割线** | 点工具栏「分割线」；或手写 `---` / `***` / `___`（独占一行、**上方留一个空行**） |

**观感**：格式模式把「上方空行换行 + `---` 行 + 该行自身的行尾换行」折叠成一个**紧贴**的规则呈现单元
（**1px `outlineVariant`** 细线、居中、无外边距、按段宽铺满），预览态是标准 `<hr>`（**1px `outlineVariant` 上边框**）
——两态都只占 **3 个视觉行**，**不出现多余空行**。

**两态段落间距目前不一致（已知待决项）**：真机格式态「段落1 → 段落2」顶距 **54.75px**，预览态 **37.02px**
（格式态比预览松 **17.73px**）。**压小呈现单元无效**——该行行高由正文 `StrutStyle` 的 **24px 下限**（为图片行而设）
与占位对齐决定，与呈现单元高度无关；已试过的「规则行以显式换行结束」在真机**更差**（4 行 / 78.75px）**已撤回**。
要一致只能改正文 strut（**空行行高会随之变小**）或调大预览间距（与「紧贴」相反），**需产品决策**，
故当前**登记为待决项**，**不是回归、也不是缺陷**。

### 在分割线上方 / 下方删字时，会不会把分割线删坏或丢字？

**不会丢字**。退格 / 删除命中分割线时是**整行移除**：只删 `---` 这一行（含它自己的行尾换行）**外加紧邻其下的
一个换行**，**上方空行保留**，正文**一字不动**。

* `段落1\n\n---\n段落2` 把光标放在「段落2」行首按一次**退格** → `段落1\n\n段落2`（两段之间的空行还在）；
* 若分割线**下方本来就有一个空行**，那个空行的换行仍按**普通删除**处理（一次只删一个换行），
  不会因此吞掉整条分割线或下一行文字；
* 光标停在**分割线行**上、或停在**紧贴它下方那一行的行首**，再点「分割线」= **移除**该行（幂等往返）。

> 详见 [用户指南 §3.14](./guides/user-guide.md) 与 [架构文档的当前状态](./architecture.md)。

### 源码模式粘贴 Windows 内容后，勾选框（任务列表）不渲染了？

**现象**：从 Windows 记事本 / Word / 网页复制的文本粘进**源码模式**后，`- [ ]` / `- [x]` 不再显示成
**勾选框**，甚至 `---` 也退化成一行普通字符；历史遗留下来的 **CRLF 笔记**（行尾是 `\r\n`）同样不渲染。
（原报障的更具体表现：CRLF 正本里**勾选框 2 个变成 1 个**、`---` 退化为字面量。）

**原因**：Windows 的换行是 `\r\n`（CRLF）。旧版扫描器把**行尾的 `\r` 当成了内容的一部分**，
于是 `- [x]` 后面凭空多了一个看不见的字符，勾选框与分割线的判定**整个失配**。
**正本本身没有丢字**——只是**扫描视图**没把它解析出来。

**怎么办**：

1. **现在已修（`v0.15.0` / FR-77）**：扫描视图对**行尾 `\r` 容错**——`\r` **不改正本字节、不影响偏移**，
   历史 **CRLF 笔记立即恢复渲染**，并且**不会产生新修订**（打开看一眼不会写库）。
2. **粘贴只做换行归一**：格式 / 源码两态粘贴时只把 `\r\n` 与 `\r` 归一成 `\n`
   （`normalizeLineEndings`）——**不套用**导入文件用的 `normalizePlainText`，
   所以**行内粘贴不会莫名多出换行**。
3. 若仍有异常，切到**源码模式**直接看正本字符，或用**笔记内查找**（`Ctrl / Cmd + F`，
   **源码模式全量参与**）搜一下可疑字符。

> **边界（如实登记）**：**真·单独的 `\r` 作行内分隔**（如 `- [ ] 甲\r- [x] 乙\r`）**不被扫描器断行**
> ——这种写法只在**粘贴归一**时被消除；用例如实锁定了这一边界。

### 格式模式下打字，正本里为什么出现了 `\`？

**现象**：格式模式里打一个 `*`，切到源码模式一看正本里是 `\*`；打 `[` 会变成 `\[`。

**原因**：这是 `v0.15.0`（**FR-78**）的**输入转义口径**——格式模式下，凡是**会改变语法树**的 ASCII 标点，
键入时会**自动转义后落正本**，以保证你看到的字符**就是**你想打的字符（而不是被解析成加粗 / 链接）。
用户在格式模式里**看到的仍是 `*` 本身**，那个反斜杠**不可见**。

**怎么办**：

1. **不用管**：这是**设计行为**（不是故障），格式 / 源码 / 预览三态往返**逐字节不变**，
   切回格式模式观感正常。
2. **想核对 / 手写正本**：切到**源码模式**——源码模式**一律原样输入**（没有自动转义），
   正本字符逐字可见、可编辑。
3. **想生成真正的结构**：**别手打** `**x**` / `~~x~~` / `==x==`——在格式模式下那会落成
   **转义字面量**（语法**不生效**）。请**选中文字后用工具栏按钮**（加粗 / 斜体 / 删除线 / 高亮…），
   或切到**源码模式**手写 Markdown。

> 详见 [用户指南 §3.21](./guides/user-guide.md)「格式模式里键入语法字符会发生什么」。

### 删除线和高亮一起用，会显示成 `==` 吗？

**现象（旧版）**：写 `~~文字==高亮==~~`（删除线包住高亮），格式模式显示出明文 `文字==高亮==`
——外层 `~~` 生效了，内层的 `==` 却漏成了普通字符。

**原因**：旧版的行内记号解析是**一次性 flat 正则**——它先匹配到最外层删除线，内层高亮的 `==`
就再没有机会被解析，于是**原样露出**。

**怎么办**：**已修（`v0.15.0` / FR-79）**。行内记号解析改为**按区间递归**——外层记号匹配后，
**在其区间内继续解析内层记号**，所以「删除线 + 高亮」同用**不再明文露出 `==`**。
**正本一字不改**（解析只发生在呈现层）。

> **反向嵌套保持现状（已知待决项）**：`==~~文字~~==`（**高亮包删除线**）目前**行为不变**——
> **格式与预览两态一致**，登记为**待决项**，本轮未改。

### 给多段文字分别加斜体后，全选再点斜体取消，为什么多出一堆 `**`？

**现象（旧版）**：对若干片段**分别**点「斜体」加斜体，再**全选**这些片段点一次「斜体」想统一取消，
结果正本里**多出大量 `**`**（本该删掉的记号没删干净，还互相咬出了新记号）。

**原因**：旧版判定「当前是否已加斜体」时只看**光标附近的一个记号**；全选状态下区间内**有多个**
斜体记号（还可能夹着加粗的 `**`），于是**判定与删除都错位**。

**怎么办**：**已修（`v0.15.0` / FR-80）**。判定改为「**区间内同类记号集合**」——全选后点斜体，
会**一次取消区间内所有同类斜体记号**；并且**只删同类**（区间里加粗的 `**` **不会被斜体吞掉**）。

> 相关能力见 [用户指南 §3.21](./guides/user-guide.md)（格式模式键入语法字符，以及「用工具栏生成结构」）。

### 网页原件显示「原件不可用」/ 内嵌网页是空白？

`v0.16.0` 起全页快照会保存一份单文件 HTML 原件并在笔记里用 **WebView** 预览。出现降级卡片时按顺序检查：

1. **Windows**：是否安装 **WebView2 Runtime**（Win10 1809+ 通常自带；可从微软官网安装
   Evergreen Runtime）。缺失时应用会降级为「整页截图 + 打开原件」，不会崩溃。
2. **Linux**：当前没有内嵌 WebView 实现，直接降级（这是已知限制）。
3. **原件尚未同步**：笔记正文与附件映射先到、HTML 字节按需拉取；等同步完成后重新打开笔记。
4. **原件超过 12 MiB**：服务端不会保存原件，只保留 Markdown + 截图（剪藏仍成功）。
5. **页面像纯 HTML、没有原站排版**：`v0.16.1` 之前的旧剪藏没有保留外部 `<link>`，
   需要**重新剪藏一次**（新版本由服务端拉取并内联跨域 CSS）。
6. **CSS 背景图 / 字体 / JS 动态内容**：属于已知限制，原件保留的是采集时刻的 DOM。

### 勾选框 / 列表操作后光标位置不对？

`v0.16.0` 起，插入勾选框后光标固定在 `- [ ] ` 行尾（可直接继续打字）；无序 / 有序列表、缩进、
标题、引用、简化格式执行后光标落在**末行行尾**，不再整行选中。若仍看到整行选中，请确认客户端
已升级到 `v0.16.0` 或更高。

## 开发类问题

### `dart test` / `flutter test` 报 `Failed to load dynamic library 'libsqlite3.so'`

drift 在原生平台需要 `libsqlite3` 动态库。WSL / Linux 常见问题是只有 `libsqlite3.so.0`
而没有 `libsqlite3.so` 符号链接：

```bash
mkdir -p ~/.local/lib
ln -sf /usr/lib/x86_64-linux-gnu/libsqlite3.so.0 ~/.local/lib/libsqlite3.so
export LD_LIBRARY_PATH=$HOME/.local/lib:$LD_LIBRARY_PATH
```

运行测试时确保该 `LD_LIBRARY_PATH` 生效。

### Web 端数据不持久化（刷新即丢）

检查 `clients/flutter_app/web/` 下是否存在 `sqlite3.wasm` 与 `drift_worker.dart.js`。
缺失任一资源时，浏览器控制台会出现 drift worker / wasm 相关报错，数据库回退为内存实现。

- 验证是否落库：DevTools 中执行 `indexedDB.databases()`，应能看到名为 `sui` 的库。
- 重新生成方式见[快速开始 §4.4](getting-started.md#44-web-端资源sqlite3wasm-与-drift-worker)。

### `flutter build web` 报 `Dart library 'dart:ffi' is not available on this platform`

平台相关能力必须走条件导入（壳文件 + `*_io.dart` / `*_web.dart`），不能无条件
`import 'dart:io'` 或 `package:drift/native.dart`。检查新增代码是否破坏了这一分层，
见[系统架构 · 平台分层](architecture.md#6-平台分层条件导入与构建目标)。

### `flutter build linux` 停在 CMake / Ninja 报错

脚手架与平台配置已就位，缺的是**宿主工具链**：

```bash
sudo apt install -y clang ninja-build pkg-config libgtk-3-dev
```

典型报错：`CMake was unable to find a build program corresponding to "Ninja"` /
`CMAKE_CXX_COMPILER not set`。Windows / macOS / iOS 需在对应宿主系统上构建。

### 找不到 `go` / `flutter` 命令

WSL（或其他环境）中工具链可能不在默认 `PATH`，需显式指定绝对路径，例如
Go 在 `/home/aiuser/go-sdk/go/bin`、Flutter 在 `/home/aiuser/flutter/bin`。

### e2e 测试偶发「连接被拒」

测试起服务端后若用固定 `sleep`，机器繁忙时服务端尚未监听会假失败。当前 e2e 已改为
轮询 `GET /healthz` 探活（100ms 一次，上限 20s）。若自建测试出现类似问题，同样改用探活。

### 修改了 drift schema 但代码没生效

drift schema 变更后必须重新生成代码：

```bash
cd clients/note_core
dart run build_runner build
```

### 桌面端启动后提示「数据目录不可用」？

说明**引导指针** `<应用支持目录>/storage.json` 指向的数据目录当前不可访问（外置盘 / 网络盘未挂载、
目录被移动或删除、权限不足）。应用会整屏阻断并给三个动作：

1. **重试**：挂载磁盘 / 修复权限后重试；
2. **改回默认目录**：在默认目录新建空库（**不会删除**原目录数据，稍后仍可手动指回）；
3. **重新指定其他路径**：直接指向数据实际所在目录。

三者都需要**重启应用**生效。排查时可查看 `storage.json` 里的 `dataDir` 是否为你期望的路径；
该文件损坏会被视为「无指针」，此时应用会用默认目录并在界面提示数据位置，请勿在原目录之外
随意写入数据，以免误判。

### 更改存储位置后没有生效 / 数据「看起来没变」？

迁移完成后必须**重启应用**才切换到新位置（连接仍指向旧目录直到重启）。若迁移失败，
应用会继续使用旧位置并给出原因（权限 / 空间不足 / 校验不一致）；旧目录**始终保留**，
不会被自动删除。
